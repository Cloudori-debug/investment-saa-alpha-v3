# 알파 시스템 UI/UX 마스터 설계서

> 이 문서는 대시보드 UI의 단일 기준(source of truth)이다.
> 개별 요청문과 충돌하면 이 문서가 우선하며, 설계 변경은 이 문서를 먼저 고친다.
> 대상: Streamlit 단일 앱 / 단독 사용자 / 폰(점검용) + PC(분석용)

---

## 0. 설계 철학 (모든 화면 판단의 상위 기준)

이 UI는 정보 표시 도구가 아니라 **규칙 준수 지원 도구**다. 모든 설계 판단은 아래 4원칙으로 환원한다.

| # | 원칙 | 의미 |
|---|------|------|
| P1 | 과제 중심 | 사용자는 화면을 구경하러 오지 않는다. "지금 할 일이 있는가 → 있다면 처리"가 유일한 여정 |
| P2 | 결정권 분리 | 규칙은 config(과거의 차분한 나), 사실 입력은 사람(도장), 판정은 시스템(자동). UI는 이 경계를 흐리지 않는다 |
| P3 | 마찰의 비대칭 | 중대할수록 마찰을 늘린다(2단계 확인), 사소할수록 줄인다(원터치). 진입은 차단, 청산은 경고 |
| P4 | 정직한 판정 | "아직 아니다"와 "판단할 수 없다"를 항상 구분. 내부 로그를 사용자에게 노출하지 않는다 |

**시스템 밖/안 경계 (모든 처리 패널 공통 하단 문구)**:
"실행(매매)은 증권사에서, 이 시스템에서는 판정과 기록을 합니다."

## 1. 정보 구조 (IA)

```
탭 내비게이션 (7개)
├─ ① 홈 ──────────── 관제탑: 액션 큐 + 트랜치 + 지표 + 데이터 상태
│    └─ 처리 패널 (오버레이 계층 — 화면 아님)
├─ ② 포트폴리오 ──── 보유 6종 감시: 불릿 리스트 + 확장 카드
├─ ③ 스코어 ───────── 유니버스 30종 평가 테이블
├─ ④ 저널 ─────────── 전체 기록 타임라인 + 유형 필터 + 기입 2종
├─ ⑤ 이벤트 입력 ──── 사실 보고 창구: go-live·T2·논지훼손·데이터 갱신·AI 검증 리포트
├─ ⑥ 규칙 ─────────── 참조 문서: 체크리스트 + 트랜치 규칙 + config 3분류
└─ ⑦ CECS 채점 ────── shortlist 30종 순차 채점 + 근거 기록
```

**사용 빈도에 따른 위계**: 홈(매번) > 포트폴리오(주 1회) > 저널·스코어(수시) >
이벤트 입력(사건 발생 시) > 규칙(가끔 참조) > CECS 채점(가동 전 집중 작업).
CECS 채점은 체크리스트 딥링크가 주 진입점이며 탭 직접 진입도 허용한다.

**딥링크 지도** (출발 → 도착, 반드시 컨텍스트 프리필):

| 출발 | 도착 |
|------|------|
| 액션 큐 항목 | 해당 항목의 처리 패널 (§3) — 화면 이동 아님 |
| T2 카드 | ⑤ 이벤트 입력, 이벤트 select 프리필 |
| T3 카드 | 이력 없음: ⑤ 데이터 갱신 섹션 / 이력 있음: 판정 상세 |
| T1·T4 카드 | ⑥ 규칙, 해당 트랜치 expander 열림 |
| 재량 이탈 지표 | ④ 저널, 재량 필터 적용 상태 |
| 포트 종목 확장 카드의 "저널 근거" | ④ 저널, 해당 종목 필터 |

## 2. 시각 시스템

### 2.1 계층 규칙 (3단 고정 — 전 화면 공통)
```
1단: 화면 컨테이너 ─ 배경 + 외곽 테두리 (테두리는 여기 하나만)
2단: 항목 행/카드 ─ 테두리 없음, hairline 구분선만
3단: 확장/상세 영역 ─ 테두리 금지. 배경 반 단계 변화 + 좌측 2px 액센트 라인으로 소속 표시
```
- 박스 안 박스 금지. 내부 정보 그룹은 소제목(11px muted) + 여백으로만 구분
- 확장/접힘 시 레이아웃 점프 금지 (컬럼 폭 고정)

### 2.2 색 — 상태 의미 전용 (장식 금지)
| 색 역할 | 사용처 | 금지 |
|---------|--------|------|
| accent | 진행률, 링크, 선택 상태 | 제목 강조 |
| success | 정상(cap 여유, 집행 완료) | — |
| warning | 임박(cap 여유<5%p, 데이터 노후), 재량 경고 | — |
| danger | 위반(cap 초과), 하드 룰 차단, 논지 훼손 | — |
| muted | 보조 정보, 소제목, 판정 불가 상태 | 본문 |

핵심 규칙: **판정 불가(데이터 부재)는 warning이 아니라 muted + 명시 문구.** 경고색은 "시장이 말하는 것"에만 쓰고, "시스템이 모르는 것"에 쓰지 않는다 (P4).

### 2.3 타이포그래피 (Streamlit 제약 내)
| 역할 | 크기/무게 | 용도 |
|------|-----------|------|
| 화면 제목 | 15px / 500 | 탭당 1개 |
| 핵심 수치 | 22px / 500 | 홈 지표 3개 등. 숫자는 tabular-nums |
| 본문·행 제목 | 13px / 400~500 | 종목명, 판정 문장 |
| 보조·소제목 | 11px / 400 / muted | 단위, as_of, 그룹 라벨 |
- 강조 수단은 크기·무게·색 중 **하나만** 사용. 겹치면 위계가 죽는다

### 2.4 문구 (UI_COPY.md 관리 원칙)
- 모든 시스템 출력은 3요소: (a) 무슨 일 (b) 왜 (c) 사용자가 할 일
- 내부 로그 문자열 노출 금지 — 전부 한국어 템플릿 매핑. 매핑 불가 시 "판정 사유 확인 필요" + 원문은 접힌 상세에만
- 능동태, 버튼은 결과를 그대로 말한다: "감축 완료 기록" (○) / "제출" (×)
- 빈 상태는 방향 제시: "오늘 할 일 없음 — 다음 판정: T3 7월 말" (○) / "데이터 없음" (×)
- 트랜치 표시명 고정: 즉시 집행분(T1) · 제도 확정 대기분(T2) · 저가 매수 대기분(T3) · 기한 보험분(T4). 원코드는 괄호 보조

## 3. 처리 패널 (과제 계층 — 이 시스템의 시그니처)

액션 큐 항목 클릭 시 화면 이동 없이 열리는 전용 뷰. **모든 패널은 3단 고정 구조**:

```
┌─────────────────────────────────────┐
│ [상황] 한 문장 — 무슨 일이 왜        │  ← 판정 문장 템플릿 재사용
│ [근거] 판단용 데이터 인라인 발췌      │  ← 다른 화면 방문 불필요
│ [처리] 행동 버튼 / 절차 명시          │  ← 저널 자동 연결
│ ───────────────────────────────────  │
│ "실행은 증권사에서, 여기서는 기록"    │  ← 공통 하단
│ 전체 화면에서 보기 →                  │  ← 기존 딥링크는 보조로 강등
└─────────────────────────────────────┘
```

### 유형별 정의

**a. 감축 신호** (cap 초과)
- 상황: "○○홀딩스 평가액 35.8% — 상한 35%를 0.8%p 초과"
- 근거: 현재 비중·평가액·감축 필요 금액(원화 환산)·초과 발생일
- 처리: [감축 완료 기록](체결가·수량 입력 필수) / [보류 기록](사유 필수 → 재량 이탈 집계)

**b. 트리거 발화 집행** (go-live 후)
- 상황: "제도 확정 대기분 발화 — 총 n원 집행 대상"
- 근거: 트랜치 금액, eligibility 통과 종목, **sizing 배분안(종목·금액 단위)**, 기존 보유 합산 cap 여유
- 처리: [집행 기록](종목별 체결가·수량) / 하드 룰 위반 상태면 버튼 없이 차단 사유만 (P3)

**c. 체크리스트 미완** (PRE_LAUNCH)
- 상황: "가동 전 — 체크리스트 n/3"
- 근거: 미충족 항목 + 해결 경로(파일명·작업 내용)
- 처리: [다시 확인](재검사 실행)

**d. 데이터 갱신 필요**
- 상황: "펀더멘털 as_of 97일 경과 (권장 분기)"
- 근거: 초과 소스·경과일·마지막 갱신 결과
- 처리: [지금 갱신] (PC 실행 조건 명시, 실패 시 사유 표시)

**e. SWAP_CANDIDATE** (관찰 모드)
- 상황: "○○지주가 보유 최하위를 +22% 초과 (2회 연속 중 1회)"
- 근거: 양측 스코어 비교, 조건(마진 20%·2회 연속) 대비 현황
- 처리: **버튼 없음** — "관찰 모드: 기록만 됩니다. 스왑 활성화는 운용 데이터 축적 후 재검토" 명시

**f. 체크리스트 미완** — 항목별 작업대로 세분화

1. **CECS 채점**
   - 상황: "CECS 채점 n/30 완료"
   - 근거: shortlist 30종 중 `final` 개수와 미채점 목록. 보유 종목을 우선 표시
   - 처리: [지금 채점하기] → ⑦ CECS 채점 화면, 첫 미채점 종목 프리필
2. **score_cutoff 미확정**
   - 상황: "컷오프 미확정"
   - 근거: CECS 완료율과 팩터 CSV·상관 리포트 생성 가능 여부
   - 처리: 채점 미완이면 버튼 없이 "채점 완료 후 활성화". 30/30이면
     [상관 리포트 생성] → 결과 인라인 표시 → **상위 N종 슬라이더/단절점 객관식**
     으로 상대 컷오프 선택(절대 점수 직접 입력 없음, cutoff는 N위 점수로 파생)
   - 컷오프 확정은 2단계 확인 후 config에 반영하고 저널 자동 기록
3. **T3 PBR 이력 부재**
   - 상황: "PBR 이력 CSV 없음"
   - 근거: 자동 산출 시도 가능 여부와 마지막 결과
   - 처리: [자동 산출 시도]. 불가능하면 필요한 파일·수동 적재 경로를 안내

완료된 체크리스트 항목은 체크 표시와 muted 상태로 조회만 허용한다.

## 4. 화면별 상세 설계

### ① 홈 — 관제탑
**단일 과업**: "자동 준비가 끝났는가 / 지금 내가 할 한 가지는 무엇인가"에
3초 안에 답한다.

모바일(1열, 위→아래 = 중요도순):
```
[치명 배너: FROZEN / WINDOW_END 만]
[자동 준비 2칸: 정량 / 정성]
  · 서로 독립적으로 판정, 정상 항목은 조작 버튼 없음
[지금 할 일 1건]
  · 정량 갱신 → 주간 요청서/업로드 → 영역 승인 → cutoff → go-live 순으로
    가장 앞선 blocker 하나만 표시
  · 정량은 홈에서 1클릭 실행, 나머지는 해당 focus로 딥링크
[제안 결과]
  · proposal_book 또는 생성 대기 사유
[운용 상태·트랜치·데이터 상세 — 기본 접힘]
  · action queue / 트랜치 / 실보유 / 전체 데이터 상태
```
수집 UX:
- 정량: `현재가·펀더멘털 → alpha_scores → provenance`를 **정량 전체 갱신 1회**로 실행
- 정성: A~E **주간 요청서 1파일** 생성·다운로드·업로드
- 최종 확인: 같은 화면의 영역별 승인판. 공통 승인자 1회 입력, 각 영역은
  출처 확인 체크 후 「이 영역만 승인」

구현: `alpha_system/ui/services/home_pipeline.py` · `pages/home.py`

### ② 포트폴리오 — 제안 북 / 운용 북 분리
**단일 과업**: 스크린 제안과 실보유를 혼동 없이 감시.

- 탭 분리:
  - **제안 북 (`proposal_book`)**: 객관 스크린(정책 B) eligibility 통과 후 `allocate_tranche` 제안 비중. 매입 단가 없음. `target_portfolio.csv` 미승인.
  - **운용 북 (`ops_book`)**: `positions.csv` 실보유 비중. cap/감축 큐·exit 판정의 기준.
- 홈 지표: `제안/보유/목표` (proposal_count / ops held / target)
- 스코어보드 진실 소스: `alpha_portfolio/data/output/alpha_scores.csv` + CECS final (dry CLI와 동일)
- 기본: 불릿 리스트 (종목당 1행)
  - 행 = 종목명 · 비중 · 목표까지 % + **바 2개 (축 분리 필수)**:
    - 가격 바: 집행 단가→목표가 사이 현재가. 손실이면 채움 0% + "-n%" 텍스트
    - 비중 바(얇게): 0→35% 스케일. ≥30% warning, ≥35% danger+감축 배지
- 확장(행 클릭, 아코디언 — 동시 1개만): 카드형 상세
- 목표가 미기입 종목:
  - 제안 북: "스크린 제안 종목, 승인 전 목표가 미설정"
  - 운용 북 신규 편입 후 미기입 → danger "목표가 없음 — 편입 규칙 위반"
  - 레거시 보유 → warning "목표가 없음 — 레거시 보유, 이행 심사 대기"

### ③ 스코어 — 유니버스 평가
**단일 과업**: 30종의 자격(eligibility)과 서열 확인.

- 테이블 유지 (카드 부적합 — 밀도 필요)
- PC: total / Q·V·SR·R / cecs / eligibility / fallback 표시 / is_held
- 모바일: 종목명·total·eligibility·보유 4열 축약
- cutoff 미확정: 컷라인 없이 정렬만 + 상단 muted "컷오프 미확정 — 자격 판정 전"
- cutoff 확정 후: 컷라인 시각 표시, 미달 보유 종목은 warning (exit 연동 예고)

### ④ 저널 — 기록과 자기검증
**단일 과업**: 무슨 일이 있었고, 내가 규칙을 얼마나 지켰는지.

- 타임라인(최신순) + 유형 필터: 전체/집행·전이/경고/차단/재량/데이터/입력
- 재량 이탈 섹션 분리 상단 고정 (누적 횟수 + 사유 목록) — 이 숫자가 커지면 규칙 재설계 신호라는 설명 툴팁
- 기입 2종: 재량 청산(경고→사유 필수→저장), 목표가 수정(펀더멘털 사유 필수 / 가격 사유 선택 시 WARN 후 저장 허용)
- append-only 명시: 정정은 취소 기록 추가로만

### ⑤ 이벤트 입력 — 사실 보고 창구
**단일 과업**: 시스템이 못 보는 세상일을 도장 찍어 알린다.

- 상단: **주간 통합 정성 요청서** (금 장후 생성 → 주말 작성 → 월 장전 영역별 승인)
  - 섹션 A~E: CECS 30 요약 / 최종6 심층 / T2 / 논지 / 목표가
  - 업로드 후 영역별 `ai_suggested` · 출처 확인 필수 · **영역별 별도 승인**
  - CECS 승인 ≠ T2/논지/목표가 자동 확정
  - 목표가 승인은 `kr_alpha_exit_targets.yaml`만 · `target_portfolio.csv` 금지
  - 상세: `docs/WEEKLY_QUAL_REPORT_SPEC.md`
- 레거시: [AI 검증 리포트 생성]은 질문지 전용(접힘)
- Go-live 선언: 체크리스트 게이트(미충족 시 항목 나열 차단) + 2단계 확인
- T2 이벤트 기록: 3종 select + 근거 URL/텍스트 필수 + "T2 집행 신호 생성" 경고 + 2단계 확인
- 논지 훼손 플래그: 사유 필수 + "미집행 전량 동결" 경고 + **3단계 확인** (최대 마찰)
- 데이터 갱신: 기본은 **정량 전체 갱신 1버튼**. 보유 데이터만 갱신은 고급
  expander에 격리

### ⑥ 규칙 — 참조 문서
**단일 과업**: 시스템이 어떤 규칙으로 움직이는지 확인 (편집 아님).

- 상단: 가동 전 체크리스트 (PRE_LAUNCH 시)
  - 텍스트 나열이 아니라 클릭 가능한 행
  - 미완 항목 클릭 → §3-f 처리 패널
  - 완료 항목은 체크+muted, 클릭 시 근거 조회만
- 트랜치별 규칙 expander (표시명 + 발화 조건 + 비중 + 기한)
- config 3분류: 잠금(스키마 검증) / 확정 / TODO(경고 배지 — 가동 전 결정 목록 역할)
- 일반 규칙은 편집 불가: "규칙 변경은 PC에서 config 파일 직접 수정 — 의도된 마찰입니다"
- 예외: `scoring.score_cutoff`만 §3-f 상관 리포트 검토 + 상대 순위(상위 N) 슬라이더 + 2단계 승인 경로로 확정 가능

### ⑦ CECS 채점 — 근거를 남기는 순차 입력
**단일 과업**: shortlist 30종을 하나씩, 근거를 남기며 채점한다.

- 진입: 홈 액션 큐 또는 규칙 탭의 CECS 체크리스트 처리 패널
- 목록 뷰:
  - 30종 전체, `final`/`draft` 상태 배지
  - 보유 종목 우선 정렬 토글
  - 행 클릭 시 해당 종목 채점 폼으로 이동
- 채점 입력 뷰:
  - 종목명·티커·보유 여부를 상단 고정
  - [전체 배치 조사 요청서 생성]:
    - 기본 대상은 미채점 종목 전체, 옵션으로 shortlist 30종 전체
    - `docs/cecs_ai_research_batch_{날짜}.md` 한 파일에 종목별 고정 스키마 블록 생성
    - `## [TICKER] 종목명` 아래 execution/pension/purpose별
      `점수 제안(0-100)`·`근거`·`출처` 빈칸을 둔다
    - 1차 출처 필수·복수 출처 전부·문장-출처 대응·확인 불가·추정 금지 규칙 포함
    - "외부 AI 도구(웹검색 가능)에 이 파일을 붙여넣어 채운 뒤 업로드" 안내
    - 생성은 `CECS_AI_RESEARCH_GENERATED` 저널에 대상 종목·시각 기록
  - [완성된 리포트 업로드]:
    - 마크다운 고정 스키마를 파싱해 종목별 3축 점수·근거·출처 추출
    - 외부 0~100 점수는 내부 0~1 스케일로 변환
    - 스키마 이탈·범위 오류 종목은 실패 목록으로 보고하고 수동 입력 유도
    - 성공 행은 `status=ai_suggested`로 원자 저장하며 `final`로 간주하지 않음
    - 업로드는 `CECS_BATCH_IMPORT` 저널에 성공·실패 종목 기록
  - AI 제안 승인:
    - 채점 목록에서 `ai_suggested` 필터·상태 배지 제공
    - 종목별 점수·근거·출처 전체를 펼쳐보고 「출처 확인」해야 승인 버튼 활성화
    - 점수·근거는 승인 전 직접 수정 가능
    - 승인 시 rationale에 원문 근거·출처 링크와
      `AI 제안 기반, 사용자 승인일 {날짜}` 태그를 부기하고 `status=final`
    - 개별 승인과 배치 승인 모두 지원하되, 배치는 모든 종목의 출처 확인 전 비활성
    - 승인 저널은 종목별 `CECS_SCORE_APPROVED`
  - execution / pension / purpose 3개 입력과 재해석 규칙 툴팁
  - 각 입력의 rationale 필수. 미입력 시 `final` 저장 차단
  - [임시 저장]은 `draft` 유지, [채점 완료]는 `status=final`
  - 완료 시 `CECS_SCORE_FINALIZED` 저널 자동 기록
  - 이전/다음 종목 이동으로 세션 하나에서 순차 채점
- 진행률 `n/30`을 상단에 고정하고 홈 액션 큐·데이터 상태와 재실행 즉시 연동
- CSV 쓰기는 원본 스키마·행 순서를 유지하고 원자적 교체로 저장한다
- `ai_suggested` 가져오기는 채점 폼에 초안을 채우지만 자동 확정하지 않는다.
  승인 게이트 밖의 rationale 자동 주입·원클릭 final은 금지한다
- 경고: "사실 조사 보조용입니다. 최종 점수·근거(rationale)는 출처 원문을 확인한 뒤
  반드시 본인이 직접 작성하세요. AI 서술의 복사·붙여넣기는 채점 목적에 어긋납니다"

## 6. 검수 기준 (구현 완료 판정)

1. 각 액션 유형: "열기 → 읽기 → 처리"가 다른 화면 방문 없이 완결되는가
2. 폰 첫 화면: 액션 큐가 스크롤 없이 보이는가 / 할 일 없음이 명시되는가
3. 모든 판정 문장: "아직 아니다"와 "판단 불가"가 구분되는가 / 내부 로그 노출 없는가
4. 계층: 확장 영역이 어느 행 소속인지 3초 안에 보이는가 / 박스 중첩 없는가
5. 축 정합: 가격 바와 비중 바가 분리돼 있는가 (회귀 테스트 유지)
6. 마찰 비대칭: T2 입력·go-live가 실수로 통과 불가한가 / 재량 청산은 사유만으로 통과되는가
7. 색: 경고색이 "시스템이 모르는 상태"에 쓰인 곳이 없는가
8. 폰 한 손: 재량 기록·이벤트 입력 폼이 한 손 조작으로 완결되는가
9. CECS: rationale 없이 `final` 저장이 차단되는가 / 완료 후 체크리스트가 즉시 갱신되는가
10. cutoff: CECS 30/30 전에는 확정 UI가 없고, 이후에도 상위 N 선택·2단계 확인 없이는 config가 바뀌지 않는가
    / 절대 점수 하드코딩 입력 없이 스크린 상대 순위로 cutoff가 파생되는가
11. CECS AI 조사: 배치 요청서 고정 스키마가 파싱 가능한가 / 업로드 직후 상태가
    `ai_suggested`인가 / 출처를 확인하지 않은 종목은 개별·배치 승인할 수 없는가
