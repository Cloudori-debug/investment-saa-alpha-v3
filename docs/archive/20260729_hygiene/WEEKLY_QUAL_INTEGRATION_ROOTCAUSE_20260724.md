## 1. 왜 두 리포트가 갈라졌나 (원인)

### 원인 A — **다른 요청서 스냅샷** (구조적, 가장 큼)

| | Claude | Cursor |
|--|--------|--------|
| report_id | `WQR-20260724-190031` | `WQR-20260724-225030` |
| 생성 시각 | 19:00대 | 22:50 |
| CECS 종수 | 29 (+삼성 pension 파서 실패) | 30 |
| 제안(E/DEEP) | 닉스·현대차·현대백화점 등 | 오리온·코웨이·현대GF·삼전·LGU+ |

같은 “7/24 주간 리포트”라도 **정량·정성 갱신 사이 제안 북이 바뀌었고**, 그 사이 요청서를 두 번 뽑았다.  
→ 목표가·심층 티커가 달라 **1:1 가격 비교가 성립하지 않음**.

### 원인 B — **CECS 루브릭이 요청서에 안 실림** (프로세스)

주간 Markdown에는 축 이름만 있고, `CECS_MANUAL_SCORING_TEMPLATE`의  
「4분기 카운트 / 연기금 추세 / 대량보유 투자목적」표가 **프롬프트에 고정돼 있지 않음**.

| | Claude | Cursor |
|--|--------|--------|
| execution | 40~80 연속값 | 0/25/50/75/100 계단 |
| pension | `_____`→잠정50 다수(46칸) | 분모효과·추세 반영 또는 `_____` |
| purpose | 보수·잠정50 | 단순투자=100 / 경영권=30 |

→ **동일 사실이어도 점수 체계가 달라 0/30 종목 완전 일치**.

### 원인 C — **T2 확정 기준 vs 조사 깊이**

UI 기준은 명확함:

- 상법: **관보 게재**만 true  
- IFRS18: **금융위/KASB 확정 고시**만 true  
- MSCI: **공식 편입 발표**만 true  

| | 동작 |
|--|------|
| Cursor | “못 찾으면 false” — **과도 보수**. 실제 2026-07-21 공포·2025-12 금융위 공포를 놓침 |
| Claude | 법령·MSCI·금융위 링크까지 찾아 **true** — 이번 재검증과 일치 |

→ Cursor false는 “기준이 틀려서가 아니라 **검색 실패/미검증**”.

### 원인 D — **병렬·단일 에이전트 조사 방식**

- Cursor 경로: 서브에이전트 분할 + 루브릭 명시 → 형식·계단은 맞지만 T2·웹 깊이는 약함  
- Claude 경로: 장문 조사 → T2·서술은 강하지만 루브릭·파서(삼성 pension URL)·제안 스냅샷이 어긋남  

### 원인 E — **시스템 설계상 “초안 이중화”가 허용됨**

영역별 승인·`ai_suggested` 전제는 **여러 AI 초안이 공존**할 수 있음.  
스냅샷 고정·루브릭 첨부·T2 원문 체크리스트가 없으면 **매주 같은 분기**가 재발함.

## 2. 재발 방지 (운영)

1. **요청서는 주 1회, 승인 직전 스냅샷만** 외부 AI에 전달 (`report_id` 고정).  
2. 요청서 생성 시 **CECS 3축 채점표 요약**을 Markdown에 삽입 (이미 C/D 완성 예는 반영됨 — A 루브릭도 동일하게).  
3. T2는 AI 점수보다 **체크리스트**: 관보 URL / FSC·KASB URL / MSCI IR URL 유무.  
4. 통합본처럼 **역할 분리**: A·E=루브릭형, C·D=원문형, 마지막에 한 파일로 병합.  
5. 업로드 전 `parse_weekly_qual_markdown`으로 영역 실패 0 확인.
