# 가치 보유·매도 규칙 업그레이드 계획서

> **상태:** 계획(미승인 구현) · **일자:** 2026-10-08 · **채팅:** SAA 알파 투자  
> **범위:** 이 저장소(v3 알파 스크리너)만 · 미국 13F/달러 구루 엔진은 **별도 트랙(비코드/후순위)**  
> **불변:** `proposal_mode: pure_qvm` · `target_portfolio.csv` 사람만 · Review-only · Core `score_m` 제외 · 코스피·코스닥·중기·단기 장부 분리

---

## 0. 한 줄 목표

**종목 선정(QVM·게이트)은 유지하고**, GPT 대화에서 정리한  
「저평가 해소·가설 훼손·비중 상한·순위 히스테리시스」를  
**이미 있는 익절 스텝·통합 매매 신호 UI에 붙여 Review 가시성과 교체 일관성을 올린다.**  
자동 주문·target 자동기입은 하지 않는다.

---

## 1. 배경 — 무엇을 업그레이드하는가

| 출처 | 채택할 결론 | 이 저장소에서의 의미 |
|------|-------------|----------------------|
| 구루/13F 문헌 | 단순 복제 약함 · 가치·품질 근거 강함 | **신규 구루 엔진 불필요** · 기존 Q/V/품질·하케다카가 본선 |
| US vs KR 분리 | 13F≠코스피 | 달러 구루는 **이 repo 밖** · 여기선 KOSPI/KOSDAQ만 |
| PER/PBR·주간 | 사용자 스크리너 유형 | 주간 점수 갱신 ↔ **월말 매매 Review** 리듬으로 매핑 |
| +10% 익절 거부 | 처분효과 | 목표가·할인 해소·비중만 익절 근거 ([`EXIT_STEP_OPS_RULE`](EXIT_STEP_OPS_RULE.md)) |
| 히스테리시스 | 매수/매도 임계 분리 | 제안 편입 vs 보유 탈락 연속 조건 강화 |
| 통합 신호 UI | 행동 / 왜 / 근거 3층 | 이미 `trade_cue_merge` + `pf-signal` — **규칙을 데이터로 채움** |

**하지 않는 것 (명시)**

- 미국 13F 수집·클로닝 백테스트 파이프라인 (별도 연구)
- Core 순위에 모멘텀(`score_m`) 혼입
- `target_portfolio.csv` / 주문 자동화
- “성공 확률 %” UI 표기 (백테스트 전 금지)

## 2. 현재 → 목표 상태

```
[현재]
  QVM 제안(중기) / 단기 위성
  익절 스텝: hold|trim|cash_half|exit_full|missing  (목표가·테제·제안탈락)
  통합 큐: 장부 배지 + 일봉 차트 → headline / why / 장부·차트 / 칩
  비중 캡·사다리·하케다카·OpenDART 게이트

[목표 — Review-only 강화]
  위 + 보유 라이프사이클 레이어:
    L1 선정·게이트     (기존, 손대지 않음 또는 품질 게이트만 명시)
    L2 보유 상태머신   (매수가능|보유|관찰|교체검토|즉시매도검토)
    L3 통합 표시       (L2 + 익절스텝 + 차트 → 한 신호 박스)
    L4 월 Review 보드  (교체 후보·비중 초과·가설 훼손만 모음)
```

## 3. 단계별 계획

### Phase 0 — 운영 스펙 고정 (문서만 · 1회 승인)

**산출물:** 이 계획서 승인 + 짧은 운영 표 1장 (아래 §4를 확정값으로)

| 항목 | 가설 초안 (백테스트 전) | 승인 시 고정 위치 |
|------|-------------------------|-------------------|
| 점수 갱신 | 파이프라인/주간 정량 갱신 유지 | 운영 가이드 |
| 일반 매매 결정 | **월 1회** Review (홈·포트폴리오) | UI 카피 |
| 즉시 대응 | 테제·하드·회계/유동성·게이트 위반 | `EXIT_STEP` S0 정렬 |
| 매수 임계 | 제안 적격·컷오프·목표가 게이트 (기존) | yaml 불변 원칙 |
| 보유 완화 | 제안에 없어도 **연속 N주** 전 관찰 | 신규 파라미터 |
| 교체 최소 갭 | 후보 점수 − 보유 점수 ≥ Δ (가설 15점/100 환산) | 설정 키 |
| 개별 비중 | 목표 상한 기존 cap · **관리 상한 초과 시 줄이기 Review** | 기존 cap + UI |
| 가격 ±10% | **자동 익절/손절 없음** | UI_COPY 명시 |
| 가격 −20% 또는 시장 대비 큰 부진 | **강제 재심사** 배지 | L2 |
| Core 모멘텀 | 중기 0 유지 · 단기/차트 Review만 | 헌장 |

**완료 기준:** 운영자가 §4 표에 “채택/수정” 체크.

---

### Phase 1 — 보유 상태머신 (데이터 · Review-only)

**목적:** “스크리너에서 한 번 떨어지면 바로 판다”를 막고, GPT의 관찰·교체검토를 코드 상태로 만든다.

| 상태 | 조건(초안) | UI |
|------|------------|-----|
| `buy_ok` | 제안 적격 · 게이트 통과 | 신규/추매 Review 가능 |
| `hold` | 실보유 · 제안 안 또는 안 · 논리 유지 | 유지 |
| `watch` | 제안 밖 1~(N−1)주 또는 순위 중위 하락 | 추가매수 금지 · 관찰 |
| `rotate_review` | 제안 밖 **N주 연속** + 교체갭 충족 | 월말 교체 후보 |
| `thesis_review` | 실적·재무·논지 훼손 후보 | 즉시 점검 (S0와 연계) |
| `cap_trim` | 개별/시장 캡 초과 | 비중 줄이기 (기존 danger/warn과 정렬) |

**구현 스케치**

- 모듈: `alpha_system/ui/services/hold_lifecycle.py` (순수 함수 · target 미기록)
- 입력: 실보유 · 현재 제안 집합 · 주간 스냅샷 이력(또는 as_of 로그) · ops/exit kind · cap
- 출력: `lifecycle_state`, `lifecycle_why`, `weeks_out` → `PortfolioRow.extra`
- 이력: `data/local/` 또는 기존 journal/runtime에 **주간 “제안 포함 여부” 비트**만 누적 (gitignore 가능)

**테스트:** 상태 전이 단위 테스트 · target/yaml 미변경 assert.

**완료 기준:** 포트 행 `extra`에 상태 키가 채워지고, 제안 1주 이탈 ≠ `exit_full`.

---

### Phase 2 — 통합 신호 박스에 L2 연결 (UI)

**목적:** 이미 만든 3층(`headline` / `why` / 장부·차트)에 **보유 상태·교체 이유**를 넣는다.

| 변경 | 내용 |
|------|------|
| `trade_cue_merge.py` | 우선순위: `thesis_review`·`exit_full` > `cap_trim`/`trim` > `rotate_review` > 차트 타이밍 > `hold` |
| `portfolio_widgets.py` | 근거 행 추가: `상태 │ 관찰 2/4주` 등 · 칩에 생명주기 |
| `UI_COPY.md` | “+10% 익절 아님 · 저평가 해소·가설·비중” 한 줄 |
| 스타일 | 기존 `pf-signal-*` 톤 재사용 (신규 테마 금지) |

**완료 기준:** 일봉 읽기 후 한 종목에 **행동 1개 + 왜 1줄 + 장부/차트/상태**가 동시에 보임.  
관련 테스트(`test_trade_cue_merge`, `test_proposal_chart`) 회귀 통과.

---

### Phase 3 — 월 Review 보드 (교체·비중·가설만)

**목적:** 매주 점수 갱신과 **월 1회 매매 결정**을 UI에서 분리해 보여 준다.

| 보드 블록 | 내용 |
|-----------|------|
| 교체 후보 | `rotate_review` · 대안 종목 1줄(점수 갭) |
| 비중 초과 | `cap_trim` · 목표 대비 초과 %p |
| 가설·테제 | `thesis_review` / S0 연계 |
| 익절 스텝 | 기존 줄이기·환금·전량 (중복 제거해 한 표로) |

위치: 포트폴리오 상단 또는 홈「월 리밸」Review 섹션 확장.  
**금지:** 원클릭 target 기입 · 주문 버튼.

**완료 기준:** 월말에 볼 목록이 한 화면에 모이고, 주중에는 관찰·차트만 갱신되는 설명이 카피에 있음.

---

### Phase 4 — 가치함정 보조 게이트 (선정 쪽 · 최소 변경)

**목적:** “PER/PBR만”의 함정을 **이미 있는 품질·하케다카·OpenDART**로 더 읽기 쉽게 만든다.  
점수 가중 대수술(VQ 35/30/20/15)은 **이 Phase에서 하지 않음** (헌장·팩터 SoT와 충돌 위험).

| 작업 | 내용 |
|------|------|
| Review 체크리스트 | 보유·교체 후보에 ROE/현금흐름/부채·게이트 hit를 **한 줄 근거**로 노출 |
| 탈락 이유 문구 | 컷·품질·하케다카 미달을 “가치함정 리스크” 카피로 연결 |
| (옵션) 관찰 플래그 | 품질  borderline → `watch` 가중 |

**하지 않음:** Core 팩터 가중 전면 재작성 · 모멘텀 Core 혼입.  
필요 시 [`ALPHA_SYSTEM_FIVE_FACTOR_REWEIGHT.md`](ALPHA_SYSTEM_FIVE_FACTOR_REWEIGHT.md) / [`FACTOR_WEIGHT_LITERATURE_AND_B_SPEC.md`](FACTOR_WEIGHT_LITERATURE_AND_B_SPEC.md) **별도 승인**.

**완료 기준:** 교체·관찰 종목에서 “왜 싼지/위험한지”가 게이트 언어로 보임.

---

### Phase 5 — 검증 (백테스트·페이퍼 · 후순위)

**목적:** GPT가 말한 A/B/C/D를 **이 시스템 언어**로 축소 검증.

| 실험 | 정의 | 벤치 |
|------|------|------|
| A0 | 현재: 제안 편입·탈락 + 기존 EXIT_STEP만 | KOSPI/KOSDAQ 해당 북 |
| A1 | A0 + 히스테리시스(N주) + 교체갭 | 동일 |
| A2 | A1 + 비중 상한 trim Review 준수(시뮬) | 동일 |
| (비범위) US 구루 | 이 repo 밖 | S&P500 |

지표: CAGR · MDD · 회전율 · 비용 가정 · **초과수익 단정 UI 금지**.  
기간·비용 가정은 운영자 승인 후 `docs/` 또는 local 노트에만.

**완료 기준:** A1이 A0 대비 회전율↓ 또는 MDD 악화 없음 중 하나 이상 + 운영자 채택 여부 기록.

## 8. 완료 정의 (전체)

5. target·순위·Core `score_m` 불변이 테스트로 보호된다.
