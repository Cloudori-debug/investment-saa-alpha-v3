## 0. 한 줄

UI는 **매매 보조(Review-only)** 다.  
**구성(목표바) · 운영(팔→유지→사) · 집합(둘다/제안만/보유만) · 나침반(태도만)** 이 어긋나면 UX 실패 — 점수 예쁨과 무관.

## 1. 설계 원칙 (전략과 1:1)

| # | UX 원칙 | 전략/불변 연결 | 화면에서 보이면 안 되는 것 |
|---|---------|----------------|---------------------------|
| P1 | 알파 = **위성** · 베타 주엔진은 앱 밖 | Charter 성공 정의 | “이 화면만으로 전 재산·지수 이기기” 암시 |
| P2 | **주문·target 사람만** | Review-only | 원클릭 주문 · target 자동 기입 버튼 |
| P3 | 중기 ≠ 단기 | 장부·점수 분리 | 한 점수에 M 섞인 중기 랭킹 · 단기→중기 전량 |
| P4 | Soft ≠ 완충 | 검증계획 §1 | Soft를 “완충구간”이라고 적기 |
| P5 | 파킹 ≠ 무위험 현금 | 단기채 ETF | “안전 현금 28%” |
| P6 | 목표바 % ≠ 계좌 % | envelope 목표 100% | “지금 계좌 비중이 이렇다” |
| P7 | 24%×N = Soft 균등 **결과** | C 동결 | “종목당 24% 고정 정책” |
| P8 | 매도 규율 ≠ 초과수익 생성 | 검증계획 §1 실현 | “팔면 알파가 생긴다” |
| P9 | 결측 ≠ Soft 미달 | 데이터 공백 | 일봉 부족을 “전략 실패/단기 고장”으로 표기 |
| P10 | 접기 = 평소 안 펴도 됨 | 인지부하 | 접기 안이 메인 할 일 |

## 2. 정보 구조 (IA)

```text
확인 ─── 데이터 갱신 (정량·RSS·가동)     ← 집행 없음
포트 ─── 오늘 매매 · 목표바 · 집합 · 카드 ← 할 일
나침반 ─ 국면·태도 · 「알파로 넘기기」   ← 참고만
백테스트─ Shadow·재현 KPI               ← 검증 산출 (주문 없음)
```

| 페이지 | 1초 메시지 | 교차검증 키 (`UI_COPY`) |
|--------|------------|-------------------------|
| 확인 | 숫자 채우기 | `approval.page_title` · `mission_caption` |
| 포트 | 팔→유지→사 | `portfolio.page_title` · `page_lead` |
| 나침반 | 태도만 · 포트로 | `economy.page_title` · `bridge_kicker` |
| 백테스트 | 성과 측정 | `backtest.*` · 총수익·MDD·회전·비용 |

## 3. 포트 레이아웃 SoT (위→아래)

| 순 | 블록 | 설계 의도 | 코드/카피 앵커 | 교차검증 질문 |
|----|------|-----------|----------------|---------------|
| 0 | **오늘 매매** | 운영 순서 고정 | `portfolio.py` `_ops_playbook_html` | 팔→유지→사 순서인가? 나침반 태도 한 줄 있는가? |
| 1 | **목표바** | 알파 100% 구성 | `alpha_envelope_board.book_slide_bar_html` | “계좌 %” 문구 없는가? 파킹=단기채인가? |
| 2 | **읽는 법** | 5초 범례 | `_ux_read_guide_html` | 구성/운영/집합/나침반/접기 있는가? |
| 3 | **중기 집합** | 보유↔제안 | `_membership_set_board_html` | 둘다=유지 · 제안만=사 · 보유만=팔 인가? |
| 4 | **중기 제안** | 사도 됨 / 안 삼 | `_render_proposal_book` · map `사도 됨` | 편입0+대기N일 때 “합격선 고장”이 **아닌가**? |
| 5 | **단기 접기** | 보조 | `sleeve_short_fold` | 제목에 “중기 안 볼 때만”? 펼치면 이 칸/지금/무시? |
| 6 | **입력 접기** | 선정 도구 | `sec_input_fold` | “오늘 매매 아님”? |
| 7 | **심화 접기** | A~E 참고 | `holdings_extra_fold` | 평소 안 펴도 됨? 매매 순서 안 뒤집음? |

### 3.1 집합 ↔ 전략 상태 (필수)

| UI 열 | 의미 | 직접 행동 | 전략 |
|-------|------|-----------|------|
| 둘 다 | 제안∩보유 | 유지 · Soft PASS면 추매만 | 잔류 |
| 제안만 | 제안−보유 | **신규 매수 검토** (≤33%) | Soft 통과분 |
| 보유만 | 보유−제안 | **축소·전량 매도 검토** | 탈락·정리 |

**혼동 금지:** 목표바 공격 3종 ≠ 실보유 7종. 리밸 계산은 집합 기준으로.

### 3.2 Soft / 결측 / 완충 (카피 검증)

| 상태 | UI에 써야 할 말 | 쓰면 안 되는 말 |
|------|-----------------|-----------------|
| Soft 미달 | 지금은 안 삼 · 조건 미달 | 완충으로 보호 중 |
| 일봉·데이터 부족 | 판정 보류 · 데이터 채운 뒤 | 단기 전략 실패 · Soft 탈락과 동일 |
| 완충 (미구현) | (표시하지 않음) 또는 “미적용” | Soft=완충 |
| 파킹 | Soft 미집행 → 단기채 | 안전 현금 |

## 5. 접기 UX 규칙 (U-Fold)

모든 주요 `st.expander` 통과 조건:

1. **제목** = 언제 펴는지 (약어·SPEC 파일명 금지: `SHORT_PROFIT_ENGINE_SPEC` 등)  
2. **첫 블록** = `pf-fold-lead`: **이 칸 / 지금 / 무시**  
3. **본문**이 맨 위「오늘 매매」순서를 뒤집지 않음  
4. 평소 **expanded=False**

체크 대상: 단기 위성 · 후보·합격선 · 심화 참고 · 회차 금액 · 급락 이력 · 관심 추적 · 나침반 근거 더 보기.

## 6. 전략 검증 KPI ↔ UI 교차표

[`V3_STRATEGY_VERIFY_PLAN.md`](V3_STRATEGY_VERIFY_PLAN.md) §4 KPI가 **어디에 보이는지** (없으면 UX 갭).

| KPI 층 | 지표 | 기대 화면 | 현재 기대 |
|--------|------|-----------|-----------|
| 알파 단독 | CAGR·초과·샤프·MDD·회전·비용차감 | 백테스트 / Shadow | 있어야 함 · **실현만 강조 금지** |
| 알파 단독 | 최대 종목·업종 비중 | 목표바 + (권장) 집중 경고 | 목표바 % · 캡 경고는 선택 |
| 가계 | 합산 MDD·총수익 | (앱 밖 또는 브리핑) | 나침반/포트에 “전 재산” 암시 금지 |
| 운영 | Soft 미달 vs 결측 분리 | 단기·제안 대기 why | **필수 개선 항목** |
| 운영 | 교체율 | Shadow 이벤트·월 리밸 | 완충 검증용 · Soft와 라벨 분리 |

검증 계획의 **C 동결**이 UI에 깨지면 안 됨: 수급 순위 재가중 UI · 중기에 M 가산 UI · target 자동쓰기 UI = **즉시 실패**.

## 7. UX 수락 체크리스트 (U1–U16)

화면 또는 카피·코드 대조 시 **전부 YES**.

| # | 항목 | 확인 방법 |
|---|------|-----------|
| U1 | 포트 최상단이 **오늘 매매(팔→유지→사)** | UI |
| U2 | 목표바에 **계좌 % 아님** · 파킹=단기채 | UI + tip |
| U3 | 집합 3열 행동 문구 일치 | UI |
| U4 | 단기 편입0·대기N → 고장/합격선 강요 문구 **없음** | UI |
| U5 | Soft ≠ 완충 문구 | 전역 검색 |
| U6 | 나침반에 **알파로 넘기기** | UI |
| U7 | 확인 페이지에 종목 집행 CTA 없음 | UI |
| U8 | 접기 제목·lead 규칙 | 샘플 3개 expander |
| U9 | 중기/단기 섹션 분리 · Core M 제외 암시 | 카피·점수 열 |
| U10 | “사도 됨 / 지금은 안 삼” (또는 동등) | proposal map |
| U11 | 보유만 = 팔 쪽 행동 | 집합·배지 |
| U12 | Review-only · 사람·HTS | 리드/캡션 |
| U13 | 24%를 고정정책으로 안 씀 | 카피·도움말 |
| U14 | 백테스트에 총수익·MDD·회전·비용 축 | 백테스트 페이지 |
| U15 | 결측(일봉 부족) ≠ Soft 미달 표기 | 단기 대기 why |
| U16 | UI_COPY 중복 키 시 **의도 문구가 최종** | `UI_COPY.md` yaml |

**독립 검증:** 외부 평가자는 본 표 + 스크린샷/카피 키로 PASS/FAIL 기록. 코드 미열람 시 “보고서상”과 “화면 실측”을 칸으로 나눈다.
